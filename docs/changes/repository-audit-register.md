# VexSign repository audit register

**Status: initial prioritized audit; not a production certification.** This register
tracks verified findings and the evidence still needed. It is intentionally
incremental: repository-wide findings are not treated as proven merely because
they appear in an imported audit narrative. Updated 2026-11-09.

## Executive status

- **No complete repository-wide, line-by-line review has been completed.** The
  current pass verified the blur implementation, IPA Explorer mutation and
  journaling paths, repository snapshot keying, native-signing boundary, CI
  triggers, and selected error/concurrency/networking baselines.
- The existing update fixes are present in the base revision. This pass does not
  revisit or claim production acceptance for those changes.
- The Library row now shows Installed / Not installed / other-version status,
  plus explicit Checking and Unknown states rather than silently omitting status
  when the probe is pending or unavailable. Signed-app rows expose quick install,
  re-sign and export actions; these primary actions share the per-app auth gate.
- Installation verification now has a 120-second maximum evidence window (with
  the shorter 30-second no-evidence cutoff). A timeout ends VexSign monitoring
  as unconfirmed; it never claims success or cancels an iOS-owned install. The
  OS-owned “Verifying installation” sheet is not emulated.
- No source change in this pass enables native account signing, CMS trust, or
  unattended renewal. Those are deliberately gated pending cryptographic and
  device evidence.
- Xcode, Swift, simulator, and device validation remain necessary. Portable
  checks cannot establish UI behavior, Apple SDK compatibility, signing, or
  installation outcomes.

## Work sequence and done criteria

1. **Preserve the baseline.** Keep production capability claims aligned with
   `tools/check-native-handoff.py`; use `make verify` and the regular PR workflows
   as portable evidence, never as Apple/device acceptance.
2. **Remediate independently verifiable crash/security defects.** The private
   blur dependency is removed in this change. Its source-level regression test
   is `tools/test_public_blur_policy.py`; Apple rendering checks remain open.
3. **Review high-risk persistence and concurrency paths.** Build a call-site-level
   list for archive writes, certificates, profiles, installation evidence,
   cancellation, and recovery. Do not mass-rewrite `try?`, singletons, or
   `@unchecked Sendable` declarations based on counts alone.
4. **Close blocked native-signing gates only with external evidence.** The
   receipt-bound handoff and explicit consent boundaries are implemented. Obtain
   genuine Apple-issued profile/CMS test material through an approved process,
   verify chain and signature handling on Apple tooling, then run signed-output
   and device acceptance before production promotion. Keep renewal authorization
   scoped, expiring, revocable and cancellable.
5. **Acceptance.** Require the matching-source Apple build and simulator suite,
   followed by documented real-device cases for signing, installation,
   keychain, pairing and recovery. Record exact source revision and artifact
   SHA-256. Until then, production readiness remains unestablished.

## Scope notes

This is a working register, not a claim that every file in the roughly thousand-
file repository has now been audited. User-provided inventory counts and risk
labels have not been independently reproduced unless specifically recorded
above. The implementation deliberately avoids enabling incomplete signing
features, changing storage formats, or restructuring unrelated managers.

### Restore and cleanup follow-up (working tree)

Tweak backup restore now writes each manifest atomically before publishing its state, surfaces write/copy failures, rolls back only directories created by that attempt, and refuses to adopt an untracked destination. Folder and tweak manifests are separate commits: a failure can leave folders or earlier backup components restored. Retry is a merge, not an all-or-nothing rollback. Other tweak-library edits still use the older log-only save path and require separate durability work.

Temporary/leftover cleanup now takes an exclusive registry lease shared with registered app operations, IPA imports and backup staging. Manual cleanup and entry deletion use the same boundary; active download staging and export outputs are excluded. Startup cleanup retains its download-recovery handling. This is not a universal filesystem lock: code paths that use temporary files without a registry lease (and external/background actors outside the process) remain a risk, and the iOS simulator/device tests for these changes have not yet run. Apple-account signing and production cloud signing remain gated on the evidence and infrastructure described in their handoff documents.

### Temporary cleanup and export follow-up

The periodic stale-directory sweeper now takes the cleanup lease rather than treating age as proof of inactivity. Manual, automatic and per-entry cleanup preserve in-process tweak staging/extraction and backup outputs whose consumers outlive their producing call; abandoned copies are still removed at launch. This is conservative: retained scratch can occupy space until its owner removes it or the next launch. Shared IPA import, repository and direct-install downloads, community-certificate import, Web Manager certificate upload, API signing and server app/certificate streaming now retain a temporary-work lease through their respective handoffs. Web app export additionally owns the source app while packaging. Certificate export removes unpacked key/password scratch files after packaging, removes its server scratch directory after streaming and its share-sheet scratch after completion. The explicitly requested ZIP still contains the private key and password and is not encrypted by this change.

Other temp users and externally owned resources have not all been audited, and a process-local lease does not coordinate external processes. UIKit share completion and Vapor stream completion need actual Apple-platform integration tests. Failure to remove scratch is logged rather than assumed successful. The working tree has not been built or tested with Xcode.

### Installation and Web Manager transfer follow-up

An `InstallationArchive` now owns a temporary-work lease for its entire lifetime, including any retained OTA response after monitoring stops; releasing the installer source-app lease no longer exposes the served IPA to cleanup. Web Manager inbox files are user-owned transfers, not cleanup leftovers. Browser and WebDAV routing import staged copies and retain the inbox original on both success and failure; manage those originals explicitly in Web Manager. Streamed uploads now write a private sibling staging file and replace the destination only after the stream finishes, synchronizes and closes; failed uploads leave the previous destination untouched. A failed WebDAV PUT is no longer scheduled for import, and the signing API no longer treats an unsuccessful upload response as a successful stream. Added filesystem/lease regression cases, pending Xcode execution and actual Vapor/WebDAV integration tests.

WebDAV MOVE now uses an atomic rename and COPY stages into a private sibling directory before publishing; unsupported replacements fail without deleting the destination. Several other temporary-file producers are still outside the lease system. These changes do not constitute iOS installation evidence or a physical-device test.
