## Reproduced server defect

`server/url_guard.public_url_error` has two related failure modes:

- With `resolve_dns=False`, `https://example.com:99999/app.ipa`,
  `https://example.com:-1/a` and `https://example.com:abc/a` return `None`
  (treated as safe), because the fast path never validates `parsed.port`.
- With deterministic `_resolve_ips` and `resolve_dns=True`, the same URLs raise
  an uncaught `ValueError` (`Port out of range 0-65535`,
  `Port could not be cast to integer value as '-1'/'abc'`).

This is reachable through `server/app_installer.py` and
`server/repo_decoder.py`, which re-check each redirect hop using
`should_resolve_dns(client)`. A malformed redirected port can therefore become
an HTTP 500 / unhandled error at a public endpoint. `server/web_signer.py`
already catches `ValueError` in its own target guard; do not generalize that
protection to the shared guard without a regression test. There is no dedicated
malformed-port test in `server/tests` at baseline.

## Other baseline findings carried into implementation

- `VexSign/Backend/Server/ManifestService.resolve` returns `candidates.first`
  when no endpoint serves. The only call site is
  `VexSign/Backend/Observable/AppInstaller.swift:409`; the resulting external
  install URL is used by `ServerInstaller+Compute.iTunesLinkExternal`. This is
  a candidate defect: a failed remote-manifest probe should not silently fall
  back to an unrelated endpoint. It needs a test before any behavior change.
- `VexSign/Utilities/Installing/InstallConfirmation.swift:520` contains
  `try? await Task.sleep(...)`. The enclosing `confirm`/monitor loops check
  `Task.isCancelled`, and a cancelled sleep returns promptly; this is an
  unverified cancellation candidate, not a confirmed bug.
- Native signing gates are intact: `SigningMethodCapabilities.swift` keeps
  `nativeAppleAccountSigning: .notIntegrated`; `tools/check-native-handoff.py`
  requires production `.appleCMS()` verifier selection; the CMS verifier uses
  pinned Apple roots and strict fail-closed checks. Do not promote the feature
  without genuine Apple CMS, negative/tamper, signing and physical-device
  evidence.
- The release workflow publishes an **unsigned** IPA. `docs/distribution/bootstrap.md`
  correctly says an ordinary iOS app cannot self-install from an unsigned IPA;
  TestFlight, Ad Hoc, Enterprise, MDM and eligible marketplace routes require
  external signing/eligibility. The experimental free-account path is gated and
  is not a bootstrap claim.
- `tools/native-promotion-evidence.py` requires genuine Apple CMS, a full device
  evidence ladder, production wiring and the absence of fixture/secret markers.
  `docs/evidence/device-acceptance-native-handoff.json` is a hint, not baseline
  evidence.
