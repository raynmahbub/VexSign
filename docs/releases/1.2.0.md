## VexSign 1.2.0

This release distributes the **standalone VexSign app**. The IPA is unsigned:
sign it with your own valid identity and compatible provisioning profile before
installation. No signing certificates, private keys or shared install-server
identity are provided in release attachments.

### What’s new

- A persistent, accessible Home import button makes starting an IPA/TIPA import
  available without scrolling back to the dashboard.
- Release notifications alert once when a newer VexSign version is discovered.
  Notifications are scheduled by app update checks; they are not push alerts.
- Settings → Updates now explains when the selected install method is unavailable,
  lets you configure the updater address, and can switch to a ready paired-device
  method instead of repeating a failed action.
- Settings → Signing Methods reports current availability and explains why a
  method cannot be selected.

### Reliability fixes

- Signing errors now identify common certificate/profile mismatches and tell you
  what to check. Accepted preflight overrides remain overrides during post-sign
  verification; unattended and batch flows remain strict.
- App and certificate deletion failures are surfaced instead of silently doing
  nothing.
- Fixed simulator test-target compile errors, including the missing `OSLog`
  import that broke the main-branch build, and corrected authenticated
  repository-update handling.

### Experimental features and limitations

Native account / anisette v3 and combined-host functionality remain experimental.
This release does not claim physical-device acceptance for native provisioning,
combined-host signing, or installation. Review the in-app signing report and
confirm the installed app on your own device.

### Download and verify

Use the attached `SHA256SUMS` and `RELEASE.json` to verify the exact artifact and
source commit. Checksums establish integrity, not Apple signing authority.
Back up important app/container data before testing.
