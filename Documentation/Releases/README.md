# Reviewed release highlights

Optionally add `<MARKETING_VERSION>.md` here (for example `1.2.0.md`) in the
version-bump PR. The release generator includes that file above the automatic
commit changelog for stable and pre-release builds of that version.

Write a short, factual summary: user-visible improvements, known issues,
compatibility changes and migration steps. Do not promise untested installation
support. Use absolute, commit-pinned image URLs for genuine, reviewed screenshots;
keep private information out of images and describe device/OS versions.

There are no captured device screenshots in the current release automation.
The bundled Home preview is explicitly labelled a design illustration. Do not
replace actual test evidence with generated imagery. Add approved screenshots in
a reviewed PR when captured; never scrape images from unrelated applications.
