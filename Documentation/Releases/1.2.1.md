## VexSign 1.2.1

This release distributes the **standalone VexSign app**. The IPA is unsigned:
sign it with your own valid identity and compatible provisioning profile before
installation. No signing certificates, private keys or shared install-server
identity are provided in release attachments.

### Signing compatibility

- Add an optional **Remove Unsupported Extensions Automatically** mode. It keeps
  extensions the selected provisioning profile covers and removes only nested
  bundles known to be uncovered. The signing log reports each removed bundle's
  path, identifier and profile pattern. Unknown coverage is left untouched, and
  the main app must still match the selected profile.
- Keep uncovered extensions as a blocking preflight issue when compatibility
  mode is disabled; with the mode enabled, show which identifiers will be
  removed instead. The engine limitation remains: nested bundles use the outer
  signing asset, so this mode is a compatibility fallback, not a guarantee that
  every feature of the app will work after installation.

### Signing and entitlement usability

- Close the signing sheet automatically after a successful run while preserving
  configured cleanup and install behavior.
- Use a single presentation state for the signing preflight and log sheets to
  avoid competing modal presentations.
- Make custom entitlement-file deletion directly accessible from each row, and
  provide a visible Delete action and confirmation for selected entitlement keys.

### Installation and verification

Use the attached `SHA256SUMS` and `RELEASE.json` to verify the exact artifact and
source commit. Checksums establish integrity, not Apple signing authority.
Back up important app/container data before testing. Compatibility behavior and
installation still require confirmation with the user's signing identity and
profile on the target device.
