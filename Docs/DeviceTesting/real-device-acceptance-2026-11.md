## 3. Installation model for VexSign itself

This is separate from VexSign installing or signing *other* apps.

| Route | Mechanism | Label | Boundary |
| --- | --- | --- | --- |
| Xcode development build | Mac/Xcode signs and installs a development IPA for a registered device; profiles expire (free Personal Team is short-lived and limited) | Blocked by external prerequisite | No Mac, Apple Account or device was available here. |
| Free Apple Developer account | Xcode-managed Personal Team, limited App IDs/devices/apps and periodic reprovisioning | Blocked by external prerequisite | Limits are Apple policy; VexSign does not bypass them. |
| Paid Developer Program | Development/ad hoc distribution with registered devices, TestFlight beta and App Store submission | Blocked by external prerequisite | Enrollment, certificates, profiles and App Store Connect are external. |
| Enterprise distribution | Enterprise program and in-house distribution | Blocked by external prerequisite | No enterprise credentials or entitlement evidence here. |
| Third-party signing providers | They may re-sign an IPA with their own identity/profile | Blocked by external prerequisite | No external service was used or endorsed; artifacts must be independently verified. |
| Companion-computer sideload | A trusted Mac/host creates the pairing record and installs the app | Blocked by external prerequisite | Requires a computer and Apple-approved tooling. |
| On-device host pairing | iOS 27+ with available RPPairing host and device confirmation | Blocked by external prerequisite | This is the only computer-free route represented in the code; it is not claimed as completed. |
| Hosted CI unsigned IPA | `VexSign-unsigned.ipa`, `distribution_method=artifactDownload`, `device_installable=false` | Unsupported | It proves build packaging checks only and is refused by the device runner preflight. |

The device runner refuses an IPA unless it carries the exact source commit,
`DTPlatformName=iphoneos`, the VexSign bundle, executable, signature and profile,
an unexpired profile, a matching team/application identifier, a listed device
UDID and a non-release channel. `VEXSIGN_DEVICE_SIGNING_IDENTITY` is redacted
from console output and logs.

## 5. Physical install path consumes verified signing output

The enforced chain is: offline IPA evidence preflight → runner device/keychain
preflight → `devicectl install app` → `devicectl launch` → optional native tests
→ optional hardware XCUITests → bound feature report check. The install
coordinator additionally requires a verified signed library artifact, checks
bundle identity, version/build, certificate expiry, profile/device authorization
and a same-device inventory refresh before reporting `installed`. A command
acknowledgement alone produces `submitted`/`unconfirmed`, never `installed`.

| Case | Label | Behavior |
| --- | --- | --- |
| Valid development IPA for this commit and UDID | Blocked by external prerequisite | Runner preflight passes only with real evidence; no run occurred. |
| Wrong commit, simulator platform, wrong bundle/team/app ID, unlisted UDID, expired profile, missing signature | Implemented but not tested | Refused by `device_ipa_preflight.py`; offline tests pass locally. |
| Interrupted install, disconnect, expired credentials, incompatible app, invalid signature | Blocked by external prerequisite | Failure/unconfirmed paths are implemented; no device observation exists. |
| Progress and cleanup | Implemented but not tested | Task phases are mapped from native stages without invented percentages; temporary handling and retry paths are source-reviewed only. |

## 9. Defects fixed in this task

1. **Concurrent device operations could share one task.** `inFlight` was checked
   separately from `begin`, which can adopt a queued task; two callers could run
   the same install twice. Replaced with an atomic main-actor subject reservation
   and terminal-phase release in `DeviceLifecycleTaskReporter`.
2. **Hardware opt-in tests were absent.** Added explicit skip-based acceptance
   tests and support so missing hardware cannot become a silent pass.
3. **An ad hoc CI IPA could be handed to a device install.** Added offline IPA
   evidence preflight inside the runner, before `devicectl` sees the artifact.
4. **Device failures lacked a reusable sanitized triage event.** Added
   `DiagnosticEvent.deviceFailure` and wired it into device lifecycle errors.
5. **Connected-state evidence was not directly tested.** Added fixture-only
   capability tests for presence, trust, transport and inventory requirements.
6. **Capability evidence had no single source of truth.** Added a generated
   20-capability matrix and a CI/portable freshness gate.
7. **Cross-module import check failed after adding device diagnostics.** Added
   the required `import NimbleExtensions` to `DiagnosticEvent.swift`.

Inherited integration fixes (download admission identity, shared identity
availability with revocation, cancelled device worker generation) remain
uncommitted in this worktree and are described in the earlier integration report.

## 12. Exact manual iPhone acceptance procedure

Run these steps on a Mac/self-hosted runner with the device connected. Record
the result in the bound reports; do not convert a skip into a pass.

0. **Prepare.** Build a development-signed IPA from this exact commit. Initialize
   both reports:
   ```bash
   python3 Tools/Audit/device-acceptance.py init --ipa IPA \
     --report .artifacts/device.json --commit "$(git rev-parse HEAD)" \
     --include-native-handoff --include-computer-free-bootstrap \
     --include-apple-account-lifecycle --include-paired-installation
   python3 Tools/Audit/feature-acceptance.py init --ipa IPA \
     --report .artifacts/features.json --commit "$(git rev-parse HEAD)"
   ```
   Verify manually that the profile lists the iPhone UDID and is unexpired.

- **A — Install, launch and relaunch (Blocked by external prerequisite).**
  Run `python3 Tools/Audit/run-device-acceptance.py --ipa IPA --device UDID
  --commit SHA --log .artifacts/device-acceptance.log`. Confirm the exact bundle
  launches, version/build match the report, then terminate and relaunch. Record
  the device model and iOS version. A successful `devicectl` command alone is
  not enough; record the observed app identity.

- **B — IPA import: valid, invalid, metadata and cleanup (Blocked by external prerequisite).**
  In Files, import the valid fixture: one library row with correct bundle ID,
  version and executable. Import the invalid fixture: it is rejected, no partial
  row remains and the task is not marked complete. Kill the app during a large
  import, relaunch and confirm no incomplete artifact is treated as valid.

- **C — Certificate pairing, expiry, Keychain, removal/replacement (Blocked by external prerequisite).**
  Import a protected PKCS#12 with the correct password; confirm Keychain-backed
  identity and expiry. Wrong password leaves prior identities intact. Replace
  the identity, remove it and confirm signing cannot proceed without a valid
  identity. Never export or log private keys.

- **D — Signing identity/profile and verification (Blocked by external prerequisite).**
  Sign a compatible IPA with a matching unexpired identity/profile; require a
  passing post-sign verification before registration. Try an incompatible
  profile and an expired identity: both must stop before a usable artifact
  exists. Confirm signature verdict before any install request.

- **E — Device install: connection, inventory, interruption (Blocked by external prerequisite).**
  Verify the device; confirm a fresh identity-bound answer. Refresh inventory
  and compare bundle/version. Install, then confirm inventory reports the exact
  version/build. Disconnect mid-operation, reconnect and retry; verify state is
  `unconfirmed`/`failed`, never a fabricated `installed`.

- **F — App management (Blocked by external prerequisite).**
  Update and reinstall only after a fresh inventory confirms the current bundle.
  Reject a downgrade. Remove only with explicit confirmation for the exact
  bundle; verify removal with a fresh device query. Preserve unrelated data.

- **G — Background/lifecycle interruption, resume and termination (Blocked by external prerequisite).**
  With notification permission granted, background the app during a long
  operation, return to foreground and confirm task reconciliation. Terminate
  and relaunch; confirm navigation and task state are usable and no stale
  connected badge remains. Low-power/memory-pressure conditions should be
  noted as observed, not inferred.

- **H — Diagnostics with controlled failure and sanitized export (Blocked by external prerequisite).**
  Trigger a controlled device failure, then open Diagnostics Center →
  Troubleshooting → export filtered events. Inspect the export: it must include
  operation ID/type, connection state, failure category, system code, duration,
  recovery, model/iOS/app version, and must not contain credentials, private
  keys, UDIDs or private paths. Attach only sanitized text evidence.

After all cases, fill the observation fields in both reports with a named
tester, timestamp, model/iOS version and non-synthetic notes, then run:
```bash
python3 Tools/Audit/device-acceptance.py check --ipa IPA \
  --report .artifacts/device.json --commit SHA \
  --include-native-handoff --include-computer-free-bootstrap \
  --include-apple-account-lifecycle --include-paired-installation --renewal
python3 Tools/Audit/feature-acceptance.py check --ipa IPA \
  --report .artifacts/features.json --commit SHA
```
If any case is skipped, the report remains pending and no release claim is made.
